# document-scanner (local Expo module, Android only)

Wraps Google ML Kit Document Scanner (`play-services-mlkit-document-scanner:16.0.0`).

## API

```ts
import { scanDocument, isScannerAvailable, DocumentScannerError } from '@modules/document-scanner';

const result = await scanDocument({ pageLimit: 50, galleryImport: true, includePdf: true });
// { cancelled: false, documentId, pages: [{ pageNumber, uri }], pdfUri, pageCount }
```

- Cancel → resolves `{ cancelled: true }` (not an error).
- Failures → rejects with `DocumentScannerError` (`code` is one of `SCANNER_ERROR_CODES`).
- Pass `documentId` to append pages to an existing document folder (use `includePdf: false`;
  the PDF will be regenerated by the app).

## Storage layout

```
filesDir/documents/{documentId}/
  original/                         reserved, empty (ML Kit gives no untouched original)
  processed/page_{scanId}_{NNN}.jpg stable file names; order is owned by the database
  document.pdf                      ML Kit PDF of the first scan session
```

ML Kit writes to the app cache; the module copies to `filesDir` (temp file + rename) and then
deletes the cache output. On failure every file written by that call is removed.

## Native rebuild rules

| Change | Needed |
|---|---|
| TS/JS only | Metro reload |
| Kotlin / `build.gradle` / `expo-module.config.json` | `npx expo run:android` |
| New native package or `app.json` plugin change | `npx expo prebuild --platform android --clean` then `npx expo run:android` |
| EAS | `eas build -p android --profile development` (prebuild runs on EAS) |

`/android` is git-ignored (CNG): never edit it by hand.

## Troubleshooting

- `SCANNER_UNAVAILABLE`: device has no/old Google Play services, or Expo Go is used (not supported).
- First launch shows a Play services "downloading" screen: the scanner UI/model is delivered on
  demand by Play services. **The first scan on a device needs internet once**; afterwards it works offline.
- Emulator: needs a "Google Play"/"Google APIs" system image; the camera is the virtual scene.
- If the Activity is destroyed while the scanner is open (e.g. "Don't keep activities"), the
  pending promise may never resolve; Expo's fallback-result callback is not functional in SDK 56.
